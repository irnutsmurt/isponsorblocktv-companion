# Security model

Assumption: the web UI may be reachable from the internet by mistake, even before setup is finished.

| Area | Behaviour |
|---|---|
| Public endpoints | `/healthz` (`{"status": "ok"}` only), static assets, `/api/auth/setup/status`, setup completion, login, passkey login, recovery. Everything else, including `/api/stream` (SSE), exports and diagnostics, requires a valid session, checked server-side on every request. |
| Bootstrap | No default account. The first account needs `SETUP_TOKEN` or a random 32-character token printed once on stdout (valid 60 min, regenerated on expiry, compared in constant time, throttled). Creation is a single `BEGIN IMMEDIATE` transaction that fails if any user or the `setup_complete` flag exists; concurrent attempts produce exactly one admin (tested). After that, bootstrap is permanently disabled, also across restarts and even if `SETUP_TOKEN` remains set. No registration endpoint exists. |
| Passwords | Argon2id via argon2-cffi (t=3, m=64 MiB, p=4, RFC 9106 second recommended option), 16-byte salt; rehashed on login if parameters change. Minimum 12 characters; up to 1 024 accepted, no truncation (tested with 503 characters). Verification runs off the event loop; unknown usernames still cost one hash. |
| Login errors and throttling | One generic message. Buckets per client IP, per username and global: progressive delay from the 3rd failure, then a block of 30 s doubling up to 15 min, reset after a 15 min quiet window or a success. No permanent lockout. State is persisted, so restarts don't reset it. |
| Sessions | 256-bit random tokens; only SHA-256 is stored. Cookie `__Host-isbtv_session` (Secure on HTTPS), HttpOnly, SameSite=Lax. Normal sessions: 24 h sliding, 7 days absolute. Remembered: fixed 30 days, survive browser and container restarts, not extended by activity. A new token on every login; logout deletes server-side. Session list shows browser/OS, IP, created, last activity; individual revoke and “sign out all devices”. Password change revokes other sessions; recovery revokes all. |
| Recent authentication | Changing the password, rotating the recovery code, registering/removing passkeys, changing public origin / timezone / API key, restoring a config backup, and downloading the diagnostic bundle require a password entry within the last 10 minutes. |
| Recovery | One single-use code (20 characters from a 32-symbol alphabet) shown at setup; only an Argon2id verifier is stored. Using it sets a new password, revokes all sessions, and issues a new code. It never disables authentication. |
| CSRF | State-changing requests must carry `X-Requested-With: fetch` (not settable cross-site without CORS, which is never enabled) and, when the browser sends `Origin`/`Referer`, it must equal the served origin or `PUBLIC_ORIGIN`. SameSite=Lax adds a second layer. |
| Fail closed | If the database cannot be opened or becomes unavailable, every authenticated request returns 503 and sign-in is impossible. |
| Forwarded headers | Only honoured from trusted proxies (`TRUSTED_PROXIES` or approved on the Access page, which requires a recent password entry). HTTPS is detected from the browser's own `Origin`/`Referer` for the same host; a client can only misreport its own connection, which grants nothing (a Secure cookie on a plain-HTTP response is not stored, and passkeys use the configured public origin). |
| Headers & limits | CSP (`default-src 'self'`, no inline script), `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: same-origin`, COOP/CORP same-origin, HSTS on HTTPS, `Cache-Control: no-store` for the API. Request bodies over 256 KiB are rejected. Untrusted text (titles, log lines, names) is rendered as text by React, never as HTML. |
| Docker | The web UI never touches the Docker socket. The `docker-gate` sidecar allows only `GET /_ping`, `GET /version`, `GET /containers/<target>/json` (environment filtered to `iSPBTV_*`, mounts and network details stripped), `GET /containers/<target>/logs` and, if enabled, `POST /containers/<target>/restart`, where `<target>` must be the configured container. Everything else returns 403 (tested: other containers, list, create, exec, stop, images). An optional shared `GATE_TOKEN` is required on every request. Mounting the socket `:ro` would not make the API read-only, so the gate is what limits it. Generic socket proxies were rejected because their restart permission requires allowing all POSTs (container create/exec). |
| Secrets in iSponsorBlockTV's config | Screen IDs and the YouTube API key never leave the server: the UI receives a hash-derived device id and the last four characters; the API key field shows `[REDACTED]`. Pairing results are held server-side behind a 15-minute single-use ticket. |
| Data files | `/data` 0700, database and logs 0600, config backups 0600. |
